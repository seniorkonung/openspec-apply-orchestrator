# 0001. Восстановление по Paseo и результатам рабочего процесса

- Status: proposed
- Date: 2026-09-07
- Originating change: orchestrate-commit-preparation

## Context

Оркестратор должен продолжать работу после остановки, включая состояния, не различимые только по Git: работающий агент или ожидание человека. Пользователь разрешил существующие workspace и сессии Paseo как источник продолжения и запретил собственный журнал прогресса в репозитории. Это ограничение относится ко всем будущим типам сессий.

## Decision

Предлагается строить сопровождение как повторное чтение Paseo, Git и OpenSpec, выбор одного действия и проверку обычного результата работы. Идентичность активного поручения определяется сохраняемыми признаками собственной сессии Paseo. Обычные артефакты, состояние репозитория и коммиты остаются результатами workflow, а конфигурация — настройками. Диагностический вывод не читается для восстановления.

CLI принимает решения по явным правилам и наблюдаемым фактам; содержательную работу и изменения репозитория выполняют агенты и участвующий пользователь. Каждый тип сессии определяет собственный наблюдаемый критерий завершения. Для подготовки коммитов видимая активная сессия восстанавливается по Paseo, а результатом является чистый Git после прекращения работы или закрытия сессии; специальный структурированный ответ и неизменяемый исходный снимок не требуются. Альтернатива с локальной базой либо служебными полями OpenSpec отклонена как противоречащая согласованной границе.

## Consequences

Видимое активное поручение может продолжаться без памяти прежнего процесса, а ручные сессии пользователя остаются вне управления. Каждый новый тип сессии должен определить достаточный для него обычный результат и правила поведения после закрытия. Для подготовки коммитов CLI не доказывает, каким способом достигнута чистота Git; содержательная корректность остаётся ответственностью агента и пользователя.
