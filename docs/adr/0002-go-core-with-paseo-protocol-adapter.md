# 0002. Ядро на Go и отдельный адаптер протокола Paseo

- Status: proposed
- Date: 2026-09-07
- Originating change: orchestrate-commit-preparation

## Context

Прикладного кода ещё нет, а Go уже присутствует в инструментах проекта. Для восстановления нужны полные метки агента, workspace, состояние работы, запросы разрешения и признак архивирования. В установленном Paseo 0.7.2 CLI сокращает некоторые снимки; прямой протокол предоставляет необходимые структурированные данные и позволяет передать первоначальный промпт вместе с созданием агента.

## Decision

Предлагается реализовать CLI на Go, отделив правила сопровождения от внешних адаптеров. Git и OpenSpec вызываются их штатными CLI. Paseo обслуживает узкий адаптер его протокола с проверкой совместимости, типизированными входными данными и контрактными испытаниями. Адаптер читает полные снимки, создаёт агента с первоначальным промптом и метками одним запросом и архивирует сессию; текст разговора не служит машинным результатом. Промпты поставляются с бинарным файлом, параметры провайдера и модели задаются конфигурацией репозитория.

Для первого change выбран локальный Linux-режим и Unix socket одного пользователя. Эти ограничения относятся к поставке этого change; дополнительный транспорт потребует расширить проверяемый контракт адаптера. Разбор человекочитаемого вывода отклонён из-за потери структуры. TypeScript SDK рассмотрен, но не выбран: отдельный runtime увеличивает состав поставки относительно существующего Go-направления.

## Consequences

Дальнейшие виды поручений могут использовать типы и сопровождение, не принимая на себя формат Paseo. Проект отвечает за совместимость выбранной части протокола и должен отклонять неподдерживаемую версию. Этот ADR фиксирует предложенный выбор, а не результат уже проведённых испытаний или подтверждение пользователем новой платформенной границы.
