# 0002. Ядро на Go и адаптер команд Paseo CLI

- Status: proposed
- Date: 2026-09-07
- Originating change: orchestrate-commit-preparation

## Context

Ядру сопровождения нужны активный workspace, однозначная принадлежность сессии, состояние работы, запросы разрешения и признак архивирования. Paseo CLI 0.7.2 умеет создать агента с первоначальным промптом, полным ID workspace и произвольными метками одной фоновой JSON-командой, фильтровать сессии по меткам, инспектировать их и архивировать. Его список сессий не возвращает метки и workspaceId, но серверные фильтры применяются до ограничения выдачи; связь можно сделать проверяемой отдельной меткой полного ID workspace и сравнением широкого и точного наборов кандидатов.

Пользователь выбрал Paseo CLI как поддерживаемую интеграционную границу. Прямой протокол потребовал бы от проекта самостоятельно поддерживать транспорт и внутренний контракт Paseo, хотя нужные операции уже представлены командами CLI.

## Decision

Предлагается реализовать оркестратор на Go, отделив правила сопровождения от внешних адаптеров. Git, OpenSpec и Paseo вызываются их штатными CLI через процессы без shell. Адаптер Paseo проверяет совместимые версии CLI и локального daemon, строго валидирует JSON известных команд и преобразует его в типизированные входные данные ядра. Он перечисляет только активные workspace, находит сессии серверными фильтрами меток, уточняет кандидата через `inspect`, создаёт агента одной фоновой командой и архивирует его по полному ID; текст разговора не служит машинным результатом.

Для первого change выбран Linux-режим с локальным daemon того же пользователя и локальными рабочим Git-каталогом и корнем change. Оркестратор не выбирает транспорт daemon и не передаёт удалённый `--host`: обнаружение socket, pipe или другого локального канала остаётся внутри Paseo CLI. Разбор человекочитаемого вывода отклонён из-за потери структуры. Прямой WebSocket-протокол отклонён как дублирование ответственности Paseo, а TypeScript SDK — как второй runtime.

## Consequences

Дальнейшие виды поручений могут использовать типы и сопровождение, не принимая на себя формат внутренних сообщений Paseo. Проект отвечает за совместимость узкого JSON-контракта команд и должен отклонять неподдерживаемые версии или форму ответа до мутаций. Вызов отдельных процессов дороже постоянного соединения, но для одной сопровождаемой сессии эта стоимость ограничена, а транспорт и протокол остаются ответственностью Paseo CLI.

Если будущей возможности понадобятся данные, которых нет в JSON-командах, сначала потребуется расширить поддерживаемый CLI-контракт или принять новое архитектурное решение; молчаливый переход к прямому протоколу не допускается. Поддержка другой платформы, удалённого daemon или сетевой файловой системы также требует отдельного пересмотра границы поставки.
