# 0003. Идентификация собственной сессии после прямой отправки

- Status: proposed
- Date: 2026-09-07
- Originating change: orchestrate-commit-preparation

## Context

Повторение запроса создания агента после потери ответа способно дублировать работу. В обработчике Paseo 0.7.2 не обнаружена дедупликация создания по `requestId`, но `create_agent_request` принимает первоначальный промпт и метки сессии одним запросом. CLI запускается пользователем вручную; перед повторным запуском после аварии пользователь может проверить Paseo.

Предварительная регистрация будущего агента закрыла бы узкое окно неопределённости, но создала бы сохраняемое состояние без сессии и без естественного способа завершения. Для этого change такая сложность и постоянная блокировка несоразмерны принятому ручному режиму.

## Decision

Предлагается создавать агента напрямую одним запросом с конфигурацией, встроенным первоначальным поручением и метками происхождения. Активная собственная сессия определяется по полному набору меток агента, workspace, cwd и отсутствию чужого родителя. Название агента и время создания не определяют принадлежность.

Собственные локальные процессы одного change сериализуются средствами ОС без файлового журнала. В одном процессе неопределённая мутация не переотправляется. После остановки новый явный запуск сначала ищет видимую активную собственную сессию: найденную продолжает, а при отсутствии снова решает по актуальному Git. Архивированные сессии не блокируют новую попытку.

Резервирование будущего запроса, идентификатор `requestKey` и состояния `reserved/finalized` не используются. Узкое окно между принятием создания daemon и видимостью сессии сохраняется как явно принятый риск ручного режима.

## Consequences

Обычное восстановление остаётся простым: после остановки CLI находит уже видимую сессию и продолжает её, а после закрытия принимает новое решение по Git. Метки происхождения не зависят от названия агента. Возможен редкий дубль, если CLI аварийно завершился после принятия запроса, но до видимости сессии, а пользователь повторно запустил его слишком рано. Решение необходимо пересмотреть до введения автоматических перезапусков, фоновых повторов или нескольких независимых владельцев поручения.
