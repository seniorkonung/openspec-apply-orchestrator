# 0003. Идентификация собственной сессии после прямой отправки

- Status: proposed
- Date: 2026-09-07
- Originating change: orchestrate-commit-preparation

## Context

Повторение команды создания агента после потери ответа способно дублировать работу. В Paseo 0.7.2 не обнаружена дедупликация создания, но `paseo run --background --json` передаёт полный ID workspace, первоначальный промпт и метки сессии одной командой. Оркестратор запускается пользователем вручную; перед повторным запуском после аварии пользователь может проверить Paseo.

Предварительная регистрация будущего агента закрыла бы узкое окно неопределённости, но создала бы сохраняемое состояние без сессии и без естественного способа завершения. Для этого change такая сложность и постоянная блокировка несоразмерны принятому ручному режиму.

## Decision

Предлагается создавать агента одним вызовом `paseo run --background --json` с конфигурацией, полным ID активного workspace, встроенным первоначальным поручением и метками происхождения. Полный ID workspace повторяется в метке `oa.workspace`. Активная собственная сессия определяется точными серверными фильтрами меток владельца, версии, change, типа и workspace, сравнением с широкой выборкой кандидатов и последующим `paseo inspect --json` для проверки cwd, состояния и отсутствия чужого родителя. Название агента и время создания не определяют принадлежность.

Собственные локальные процессы одного change сериализуются средствами ОС без файлового журнала. Завершение `paseo run` без проверенного JSON после возможной передачи команды считается неопределённым исходом и не повторяется в том же процессе. После остановки новый явный запуск сначала ищет видимую активную собственную сессию через Paseo CLI: найденную продолжает, а при отсутствии снова решает по актуальному Git. Архивированные сессии не запрашиваются при выборе действия и не блокируют новую попытку.

Резервирование будущего запроса, идентификатор `requestKey` и состояния `reserved/finalized` не используются. Узкое окно между принятием создания daemon и видимостью сессии сохраняется как явно принятый риск ручного режима.

## Consequences

Обычное восстановление остаётся простым: после остановки оркестратор находит уже видимую сессию командами Paseo CLI и продолжает её, а после закрытия принимает новое решение по Git. Метки происхождения не зависят от названия агента и явно связывают его с полным ID workspace. Возможен редкий дубль, если оркестратор аварийно завершился после принятия команды daemon, но до видимости сессии, а пользователь повторно запустил его слишком рано. Решение необходимо пересмотреть до введения автоматических перезапусков, фоновых повторов или нескольких независимых владельцев поручения.
