## ADDED Requirements

### Requirement: Проверка среды и выбранного change

CLI MUST принимать явно указанный активный OpenSpec change и проверять рабочий Git-репозиторий, доступность OpenSpec и совместимого `paseo` CLI, локальный daemon Paseo того же пользователя и разрешение корней проекта и change. Корректность конфигурации новой сессии MUST проверяться до запуска агента, но только после разрешения существующей активной собственной сессии и подтверждения необходимости создать новое поручение. Схема change MUST NOT ограничиваться `intent-driven`; наличие плана, задач и ревью не является условием подготовки коммитов. Ошибка чтения MUST отличаться от отсутствия работы. Оценка того, можно ли безопасно сформировать коммиты из текущего состояния Git, MUST оставаться ответственностью агента в созданной сессии.

Поддерживаемая этим change среда MUST быть ограничена Linux и локальными рабочим Git-каталогом и корнем выбранного change. Взаимодействие с Paseo MUST выполняться только командами `paseo` и их JSON-выводом; прямое подключение к внутреннему протоколу daemon MUST NOT использоваться. Иная ОС, удалённый daemon, несовместимая версия CLI или daemon, сетевой рабочий каталог либо невозможность установить поддерживаемое локальное владение change MUST приводить к объясняющей ошибке до создания, архивирования или иного изменения workspace и сессий Paseo.

#### Scenario: Change использует другую схему
- **GIVEN** активный change существует и использует схему без плана фаз
- **WHEN** пользователь запускает подготовку коммитов
- **THEN** CLI проверяет среду и переходит к обнаружению существующего поручения без требования создать план

#### Scenario: OpenSpec недоступен
- **WHEN** CLI не может получить сведения о выбранном change
- **THEN** команда сообщает ошибку источника, завершается неуспешно и не запускает агента

#### Scenario: Среда не поддерживается
- **GIVEN** рабочий каталог находится на сетевой файловой системе либо Paseo доступен только через удалённый daemon
- **WHEN** пользователь запускает подготовку коммитов
- **THEN** CLI объясняет неподдерживаемую границу, завершается неуспешно и не создаёт и не изменяет workspace или сессию

#### Scenario: Версии Paseo несовместимы
- **GIVEN** установленный `paseo` CLI или локальный daemon не соответствует проверяемому JSON-контракту адаптера
- **WHEN** CLI проверяет среду
- **THEN** команда сообщает обнаруженные версии и не выполняет изменяющие команды Paseo

### Requirement: Настройки агента и поставка промптов

При запуске CLI MUST не более одного раза прочитать файл конфигурации рабочего репозитория и сохранить неизменяемый снимок содержимого либо ошибку этого чтения. Изменение файла MUST применяться только после перезапуска CLI. Когда требуется создать новую сессию подготовки коммитов, CLI MUST получать её параметры из сохранённого снимка. Пользователь MUST задавать точные идентификаторы поддерживаемого встроенного провайдера Paseo и модели; reasoning является необязательным. Режим разрешений и дополнительные параметры провайдера MUST NOT быть пользовательскими настройками этого формата. Наличие и корректность снимка, настроек будущей сессии и встроенного промпта MUST NOT быть предварительным условием обнаружения, наблюдения, передачи человеку либо архивирования уже существующей активной собственной сессии.

До любой изменяющей команды Paseo для новой сессии адаптер MUST проверить провайдер, модель и reasoning по структурированному немутирующему каталогу совместимого `paseo` CLI и преобразовать их в проверенные настройки. Адаптер MUST выбрать по провайдеру точный режим полного доступа, подтверждённый для совместимой версии, и MUST передать его при создании каждой новой сессии. Эта гарантия MUST относиться к проверенным параметрам вызова Paseo: установленные пользователем плагины Paseo и выполняемые ими последующие преобразования считаются доверенной пользовательской политикой, которую CLI MUST NOT инспектировать или использовать как основание для отказа. Если провайдер является пользовательским профилем, отсутствует в поддерживаемой таблице полного доступа, модель или reasoning отсутствуют в каталоге либо каталог нельзя достоверно прочитать, CLI MUST сообщить причину до создания или изменения workspace и сессии. Переход к режиму Paseo по умолчанию или повторный запуск с ослабленными разрешениями MUST NOT выполняться.

Рабочий промпт MUST поставляться с CLI. Конфигурация MUST NOT содержать режим разрешений, дополнительные параметры провайдера, промпты или прогресс поручений. Неизвестное поле MUST отклоняться с путём до него.

#### Scenario: Codex запускается с полным доступом
- **GIVEN** в конфигурации заданы поддерживаемые значения провайдера `codex`, модели и reasoning для подготовки коммитов
- **WHEN** CLI проверяет каталог и создаёт новую сессию этого типа
- **THEN** Paseo получает заданные пользователем значения, системный режим `full-access` и встроенное поручение CLI

#### Scenario: Пользователь установил плагин, изменяющий запуск Paseo
- **GIVEN** совместимый Paseo содержит включённый пользовательский плагин
- **WHEN** CLI проверяет настройки и создаёт новую сессию
- **THEN** CLI не инспектирует и не блокирует plugin-топологию, передаёт Paseo проверенные параметры своего вызова, а последующие преобразования плагина остаются пользовательской политикой

#### Scenario: Значение отсутствует в каталоге
- **GIVEN** конфигурация задаёт модель или reasoning, отсутствующие в каталоге выбранного поддерживаемого провайдера
- **WHEN** CLI проверяет настройки новой сессии
- **THEN** команда указывает проблемное значение и не создаёт и не изменяет workspace или сессию

#### Scenario: Пользователь пытается задать режим разрешений
- **GIVEN** конфигурация содержит поле режима разрешений
- **WHEN** CLI читает конфигурацию
- **THEN** команда указывает путь неизвестного поля и не выполняет изменяющие команды Paseo

#### Scenario: Профиль Paseo не входит в таблицу полного доступа
- **GIVEN** конфигурация задаёт пользовательский профиль либо встроенный провайдер без проверенного режима полного доступа
- **WHEN** CLI проверяет настройки новой сессии
- **THEN** команда объясняет неподдерживаемый провайдер и не выполняет изменяющие команды Paseo с режимом по умолчанию или ослабленными разрешениями

#### Scenario: Файл конфигурации отсутствует при восстановлении
- **GIVEN** активная собственная сессия подготовки коммитов уже существует, а однократное чтение файла конфигурации при запуске завершилось ошибкой
- **WHEN** пользователь повторно запускает CLI для того же change
- **THEN** CLI сохраняет ошибку снимка, восстанавливает сопровождение той же сессии без требования настроек создания и не запускает нового агента

#### Scenario: Настройки будущей сессии больше не поддерживаются
- **GIVEN** активная собственная сессия подготовки коммитов уже существует, а текущая конфигурация содержит неподдерживаемые provider, model или reasoning
- **WHEN** пользователь повторно запускает CLI для того же change
- **THEN** CLI не проверяет каталог настроек как условие восстановления, сопровождает ту же сессию и не запускает нового агента

#### Scenario: Настройки будущей сессии изменены во время запуска
- **GIVEN** CLI сохранил снимок конфигурации и ещё не создавал новую сессию
- **WHEN** пользователь изменяет provider, model или reasoning в файле конфигурации
- **THEN** текущий процесс продолжает использовать сохранённый снимок, а новые настройки могут примениться только после перезапуска CLI и только к следующей новой сессии

### Requirement: Одно ограниченное поручение подготовки коммитов

После разрешения активных собственных сессий CLI MUST заново читать Git. При наличии изменений индекса, отслеживаемых файлов или неотслеживаемых неигнорируемых файлов CLI MUST создать одну собственную сессию и передать ей одной командой Paseo CLI встроенное поручение подготовки всех текущих изменений. При отсутствии изменений и активного собственного поручения CLI MUST успешно завершаться без агента. Игнорируемые файлы MUST NOT добавляться принудительно.

Поручение MUST требовать сохранить пользовательские изменения в осмысленных коммитах, соблюдать инструкции и проверки репозитория и сообщать затруднения в текущей сессии. Оно MUST предупреждать агента не разрешать конфликты по догадке, не исправлять код только ради прохождения проверки, не обходить hooks, не публиковать коммиты, не переписывать ранее существовавшую историю и не отбрасывать изменения. Анализ состояния Git, выбор состава коммитов, изменения индекса и создание коммитов являются ответственностью агента; CLI MUST только решать, нужна ли сессия, наблюдать её и проверять итоговую чистоту Git.

#### Scenario: Изменений нет
- **GIVEN** существующее поручение отсутствует и Git сообщает чистое дерево
- **WHEN** CLI завершает проверку актуального состояния
- **THEN** команда сообщает об отсутствии работы и завершается успешно без запуска агента

#### Scenario: Нужно закоммитить новые и изменённые файлы
- **GIVEN** незавершённого поручения нет, а Git показывает изменения отслеживаемого файла и новый неигнорируемый файл
- **WHEN** CLI формирует поручение
- **THEN** один агент получает оба изменения вместе с требованием соблюсти правила разделения коммитов репозитория

#### Scenario: Агент обнаружил конфликтное состояние Git
- **GIVEN** текущее состояние Git нельзя безопасно закоммитить без решения пользователя
- **WHEN** агент анализирует переданное поручение
- **THEN** агент не выбирает решение по догадке, объясняет проблему в текущей сессии и ожидает участия пользователя

#### Scenario: Проверка коммита обнаружила проблему кода
- **GIVEN** агент не может создать допустимый коммит из-за проверки репозитория
- **WHEN** агент сообщает о затруднении
- **THEN** CLI передаёт текущую сессию человеку и не поручает исправить код или обойти проверку

### Requirement: Проверяемое завершение подготовки коммитов

Пока собственный агент выполняет ход, CLI MUST ожидать завершения текущего ответа той же сессии через `paseo wait <полный-id> --json` независимо от промежуточного состояния Git и MUST NOT заменять это ожидание повторным опросом `inspect`. Результат `wait` MUST служить только сигналом перечитать авторитетные источники и MUST NOT сам по себе означать успех поручения или закрытие сессии. После возврата `wait` CLI MUST заново получить активный workspace, отфильтрованные собственные сессии и `paseo inspect --json`; только подтверждённое прекращение хода разрешает заново прочитать Git. Чистое дерево MUST означать успешное завершение поручения: если сессия ещё активна, CLI MUST архивировать её, подтвердить архивирование и завершить команду. Грязное дерево MUST означать потребность в человеке, а не автоматический запуск ещё одного агента.

Если пользователь сам закрыл переданную ему сессию, CLI MUST заново прочитать Git. При чистом дереве команда MUST завершиться успешно; при грязном — завершить текущий запуск с объясняющей ошибкой. Закрытая сессия с грязным Git MUST NOT постоянно блокировать будущую явную команду: при следующем запуске отсутствие активной собственной сессии и наличие изменений снова разрешают одно новое поручение.

CLI MUST NOT требовать специального структурированного ответа агента, восстанавливать неизменяемый снимок исходного содержимого или доказывать диапазон созданных коммитов. Критерием CLI является только отсутствие незакоммиченных изменений после завершения работы сессии. Ответственность за то, что изменения сохранены корректно, а не отброшены, несут агент и участвующий пользователь. Подготовка коммитов MUST NOT запускать следующий шаг Apply workflow.

#### Scenario: Агент закончил при чистом Git
- **GIVEN** собственный агент больше не выполняет ход и Git не содержит незакоммиченных изменений
- **WHEN** CLI проверяет итоговое состояние
- **THEN** CLI архивирует активную сессию, подтверждает архивирование и сообщает успешное завершение одного поручения

#### Scenario: Длительный ход ожидается через Paseo
- **GIVEN** собственный агент продолжает выполнять ход
- **WHEN** текущий ответ ещё не завершён
- **THEN** CLI сохраняет одну блокирующую команду `paseo wait` и показывает локальный прогресс без повторного опроса `inspect` и без проверки промежуточной чистоты Git

#### Scenario: Wait сообщил о завершении хода
- **GIVEN** CLI ожидал работающую собственную сессию через `paseo wait`
- **WHEN** команда ожидания возвращает результат
- **THEN** CLI подтверждает актуальное состояние той же сессии через фильтры и `inspect`, после чего проверяет Git только если агент действительно перестал выполнять ход

#### Scenario: Агент закончил при грязном Git
- **GIVEN** собственный агент больше не выполняет ход, но Git содержит незакоммиченные изменения
- **WHEN** CLI проверяет итоговое состояние
- **THEN** CLI уведомляет пользователя и продолжает наблюдать ту же сессию без нового агента

#### Scenario: Пользователь завершил работу вместе с агентом
- **GIVEN** пользователь помог текущему агенту, изменения закоммичены и пользователь закрыл сессию
- **WHEN** CLI замечает закрытие и перечитывает Git
- **THEN** команда завершается успешно без структурированного отчёта агента

#### Scenario: Пользователь закрыл сессию при оставшихся изменениях
- **GIVEN** пользователь закрыл переданную ему сессию, а Git остаётся грязным
- **WHEN** CLI проверяет закрытую сессию
- **THEN** текущий запуск завершается неуспешно, а следующая явная команда может создать новое поручение
