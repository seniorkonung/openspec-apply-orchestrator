## ADDED Requirements

### Requirement: Однозначная принадлежность workspace и сессий

CLI MUST связывать активный workspace change с каноническим рабочим каталогом, корнем OpenSpec и выбранным change, находить его при продолжении и создавать при первом запуске, когда требуется поручение. Workspace MUST обнаруживаться через JSON-список активных workspace Paseo по служебному детерминированному имени и каноническому рабочему каталогу; архивированные workspace MUST NOT читаться или повторно использоваться. Для работы MUST быть выбран ровно один соответствующий активный workspace.

Сессия MUST считаться собственной только при точном совпадении проверяемых меток владельца, версии, change, типа поручения и полного ID workspace, а также подтверждённых через `paseo inspect --json` рабочего каталога, состояния и отсутствия чужого родителя. CLI MUST получать кандидатов серверной фильтрацией `paseo ls --global --label ... --json`; общий каталог, похожее название или принадлежность workspace без полного набора меток недостаточны. Кандидат с метками владельца и change, который не проходит точный фильтр версии, типа или workspace, MUST создавать препятствие, а не считаться отсутствием собственной сессии.

Ручные сессии пользователя MUST оставаться вне управления: CLI не ждёт их, не закрывает их и не использует их ответы как результат поручения. При нескольких подходящих workspace или несовместимых признаках принадлежности CLI MUST сообщать неоднозначность и не выбирать запись по времени создания.

#### Scenario: Пользователь работает в том же workspace
- **GIVEN** в workspace change работает ручная сессия пользователя и нет активной собственной сессии
- **WHEN** CLI проверяет возможность подготовки коммитов
- **THEN** активность ручной сессии не вызывает ожидание и не делает её объектом сопровождения

#### Scenario: Обнаружены два подходящих workspace
- **WHEN** Paseo возвращает два workspace с признаками выбранного change
- **THEN** CLI сообщает их идентификаторы и препятствие продолжению, не создавая поручение ни в одном из них

#### Scenario: Архивированный workspace остался в истории
- **GIVEN** прежний workspace change архивирован, а соответствующего активного workspace нет
- **WHEN** CLI проверяет, где продолжить или создать поручение
- **THEN** архивированный workspace не участвует в выборе и при необходимости создаётся новый активный workspace

### Requirement: Последовательность собственных поручений выбранного change

CLI MUST сопровождать не более одной активной собственной сессии выбранного change, включая ожидание человека. Перед новым поручением CLI MUST получить через точные фильтры меток активные собственные сессии выбранного change и его активного workspace и различить отсутствие, одну сессию и неоднозначное множество. Архивированные сессии MUST считаться историей, не запрашиваться для выбора следующего действия и MUST NOT блокировать отдельное новое поручение. Два одновременно запущенных экземпляра CLI для одного выбранного change MUST NOT создавать конкурирующие поручения; второй экземпляр MUST завершаться с объяснением занятости. Внутренний субагент рабочего агента не является самостоятельным следующим шагом workflow и MUST NOT приниматься за его результат.

Собственные поручения других change MUST NOT считаться активными поручениями выбранного change и сами по себе MUST NOT препятствовать его запуску. CLI MUST NOT пытаться определять, безопасна ли параллельная работа разных change по их веткам, worktree, затронутым путям или текущему действию. Выбор изоляции и последовательности такой работы остаётся за пользователем; состояние Git оценивается только для текущей команды и не служит основанием управлять чужой сессией.

#### Scenario: Повторный запуск при работающем CLI
- **GIVEN** один экземпляр CLI уже сопровождает поручение выбранного change
- **WHEN** пользователь запускает второй экземпляр для того же change
- **THEN** второй экземпляр сообщает о занятости change и завершается без создания или изменения сессий

#### Scenario: В том же репозитории работает поручение другого change
- **GIVEN** собственная сессия change A продолжает работу в том же Git-репозитории
- **WHEN** пользователь запускает CLI для change B
- **THEN** CLI не принимает сессию change A за поручение change B и не блокирует новый запуск только из-за её существования

#### Scenario: Обнаружены две активные собственные сессии
- **WHEN** CLI находит две активные собственные сессии выбранного change
- **THEN** CLI сообщает неоднозначность и не выбирает одну из них автоматически

### Requirement: Восстановление видимой активной сессии

После остановки CLI MUST восстанавливать сопровождение по JSON-результатам команд `paseo workspace ls`, `paseo ls` и `paseo inspect` вместе со свежим Git и OpenSpec. Собственный журнал прогресса, служебные поля в артефактах, состояние в конфигурации, неизменяемый исходный снимок, прямой протокол Paseo или восстановление из диагностических логов MUST NOT использоваться.

Входы, необходимые только для создания новой сессии, включая её текущие настройки и первоначальный промпт, MUST NOT быть условием обнаружения, наблюдения, передачи человеку или архивирования уже существующей активной собственной сессии. CLI MUST получать и проверять такие входы только после того, как свежие наблюдения подтвердили отсутствие активной собственной сессии и необходимость создать новое поручение.

Существующая активная собственная сессия MUST иметь приоритет перед новым поручением независимо от чистоты дерева. При работающем агенте CLI MUST наблюдать ту же сессию; когда агент не работает — проверить Git и либо завершить автономную сессию, либо передать её человеку. Остановка CLI MUST NOT сама по себе останавливать или удалять агента Paseo.

#### Scenario: CLI остановлен во время работы агента
- **GIVEN** собственный агент продолжает подготовку коммитов после остановки CLI
- **WHEN** пользователь снова запускает CLI для того же change
- **THEN** CLI находит и сопровождает ту же сессию без повторного рабочего поручения и нового агента

#### Scenario: Коммиты созданы до остановки CLI
- **GIVEN** агент создал коммиты и перестал работать, но CLI остановлен до проверки и закрытия сессии
- **WHEN** CLI возобновляет работу
- **THEN** CLI находит активную сессию, проверяет актуальный Git, закрывает её при чистом дереве и не запускает повторную подготовку

#### Scenario: Конфигурация новой сессии удалена во время существующего поручения
- **GIVEN** активная собственная сессия уже создана, а текущая конфигурация новой сессии отсутствует
- **WHEN** CLI возобновляет сопровождение выбранного change
- **THEN** CLI находит и сопровождает ту же сессию без требования восстановить конфигурацию и без создания замены

#### Scenario: Конфигурация новой сессии стала некорректной
- **GIVEN** активная собственная сессия уже создана, а её текущие настройки для будущего запуска повреждены или больше не поддерживаются
- **WHEN** CLI возобновляет сопровождение выбранного change
- **THEN** CLI не проверяет эти настройки как условие восстановления, сопровождает ту же сессию и не создаёт замену

#### Scenario: CLI остановлен после закрытия сессии
- **GIVEN** собственная сессия уже архивирована в Paseo и Git остаётся чистым
- **WHEN** CLI возобновляет работу
- **THEN** CLI завершается по актуальному Git без повторного агента и без восстановления архивированной истории

#### Scenario: После завершённого поручения появилась новая работа
- **GIVEN** предыдущее поручение проверено и окончательно завершено, его коммиты сохранены, а пользователь подготовил новые изменения
- **WHEN** пользователь отдельно запускает подготовку коммитов
- **THEN** CLI различает завершённое поручение и новые изменения и может выдать одно новое поручение в том же workspace

### Requirement: Прямая отправка через Paseo CLI и граница восстановления

CLI MUST создавать агента одним вызовом `paseo run --background --json`, который одновременно содержит его настройки, полный ID активного workspace, встроенное первоначальное поручение и метки происхождения, включая полный ID workspace. Перед вызовом CLI MUST получить актуальный отфильтрованный список активных собственных сессий. Неопределённый исход создания — завершение процесса без проверенного JSON-результата после возможной передачи команды Paseo — MUST завершать текущий запуск с ошибкой и MUST NOT вызывать автоматическое повторение мутации в том же процессе.

При следующем явном запуске CLI MUST сначала искать видимую активную собственную сессию: найденная сессия продолжается, несколько найденных сессий создают препятствие. Если активная сессия не видна, решение снова принимается по актуальному Git: чистое дерево означает отсутствие работы, грязное разрешает одну новую сессию. Предварительное резервирование запроса, ожидание по тайм-ауту как доказательство отсутствия агента и постоянная блокировка по архивированной истории MUST NOT использоваться.

#### Scenario: Потерян ответ на создание агента
- **GIVEN** команда `paseo run` могла создать агента, а оркестратор не получил проверяемый JSON-результат
- **WHEN** текущий процесс обрабатывает неопределённый исход
- **THEN** CLI сообщает ошибку и не повторяет команду создания автоматически

#### Scenario: Пользователь повторно запускает CLI после прерванного создания
- **GIVEN** предыдущий CLI остановился во время создания, а пользователь проверил состояние Paseo перед повторным запуском
- **WHEN** новая команда читает активные собственные сессии
- **THEN** она продолжает найденную сессию, а при её отсутствии заново решает по актуальной чистоте Git, нужна ли новая попытка

### Requirement: Решения принимаются по актуальным источникам

CLI MUST повторно читать Git, сведения о change и состояние Paseo во время сопровождения и ожидания человека. Перед каждым новым воздействием и подтверждением результата CLI MUST проверять актуальность его оснований. Пропадание change, смена рабочего контекста или любая ошибка чтения источника MUST завершать текущий запуск с объясняющей ошибкой без нового воздействия и без признания успеха. CLI MUST NOT ожидать восстановления источника или автоматически повторять неуспешное чтение в том же запуске. Существующая сессия Paseo MUST оставаться доступной, а следующий явный запуск MUST заново прочитать OpenSpec, Paseo и Git до выбора действия. Ожидание MUST прерываться по сигналу пользователя с сохранением возможности продолжить сессию.

#### Scenario: Источник недоступен во время ожидания
- **GIVEN** CLI ожидает ответа своей сессии
- **WHEN** соединение с Paseo становится недоступным
- **THEN** CLI показывает недоступность, завершает текущий запуск неуспешно без воздействия на сессию, а следующий явный запуск восстанавливает сопровождение только после полного повторного чтения источников

#### Scenario: Ошибка чтения перед воздействием
- **GIVEN** актуальное действие могло бы создать или архивировать сессию
- **WHEN** чтение OpenSpec, Paseo или Git завершается ошибкой перед воздействием
- **THEN** CLI не выполняет воздействие, не признаёт результат успешным и завершает текущий запуск с объясняющей ошибкой
