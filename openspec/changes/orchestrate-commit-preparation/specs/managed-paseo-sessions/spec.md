## ADDED Requirements

### Requirement: Однозначная принадлежность workspace и сессий

CLI MUST связывать workspace change с каноническим рабочим каталогом, корнем OpenSpec и выбранным change, находить его при продолжении и создавать при первом запуске, когда требуется поручение. Для работы MUST быть выбран ровно один соответствующий workspace. Сессия MUST считаться собственной только при явных признаках происхождения и связи с поручением; общий каталог, похожее название или принадлежность workspace недостаточны.

Ручные сессии пользователя MUST оставаться вне управления: CLI не ждёт их, не закрывает их и не использует их ответы как результат поручения. При нескольких подходящих workspace или несовместимых признаках принадлежности CLI MUST сообщать неоднозначность и не выбирать запись по времени создания.

#### Scenario: Пользователь работает в том же workspace
- **GIVEN** в workspace change работает ручная сессия пользователя и нет активной собственной сессии
- **WHEN** CLI проверяет возможность подготовки коммитов
- **THEN** активность ручной сессии не вызывает ожидание и не делает её объектом сопровождения

#### Scenario: Обнаружены два подходящих workspace
- **WHEN** Paseo возвращает два workspace с признаками выбранного change
- **THEN** CLI сообщает их идентификаторы и препятствие продолжению, не создавая поручение ни в одном из них

### Requirement: Последовательность собственных поручений выбранного change

CLI MUST сопровождать не более одной активной собственной сессии выбранного change, включая ожидание человека. Перед новым поручением CLI MUST прочитать все доступные активные собственные сессии выбранного change. Архивированные сессии MUST считаться историей и MUST NOT блокировать отдельное новое поручение. Два одновременно запущенных экземпляра CLI для одного выбранного change MUST NOT создавать конкурирующие поручения; второй экземпляр MUST завершаться с объяснением занятости. Внутренний субагент рабочего агента не является самостоятельным следующим шагом workflow и MUST NOT приниматься за его результат.

Собственные поручения других change MUST NOT считаться активными поручениями выбранного change и сами по себе MUST NOT препятствовать его запуску. CLI MUST NOT пытаться определять, безопасна ли параллельная работа разных change по их веткам, worktree, затронутым путям или текущему действию. Выбор изоляции и последовательности такой работы остаётся за пользователем; состояние Git оценивается только для текущей команды и не служит основанием управлять чужой сессией.

#### Scenario: Повторный запуск при работающем CLI
- **GIVEN** один экземпляр CLI уже сопровождает поручение выбранного change
- **WHEN** пользователь запускает второй экземпляр для того же change
- **THEN** второй экземпляр сообщает о занятости change и завершается без создания или изменения сессий

#### Scenario: В том же репозитории работает поручение другого change
- **GIVEN** собственная сессия change A продолжает работу в том же Git-репозитории
- **WHEN** пользователь запускает CLI для change B
- **THEN** CLI не принимает сессию change A за поручение change B и не блокирует новый запуск только из-за её существования

#### Scenario: Обнаружены две активные собственные сессии
- **WHEN** CLI находит две активные собственные сессии выбранного change
- **THEN** CLI сообщает неоднозначность и не выбирает одну из них автоматически

### Requirement: Восстановление видимой активной сессии

После остановки CLI MUST восстанавливать сопровождение по workspace и видимым активным собственным сессиям Paseo вместе со свежим Git и OpenSpec. Собственный журнал прогресса, служебные поля в артефактах, состояние в конфигурации, неизменяемый исходный снимок или восстановление из диагностических логов MUST NOT использоваться.

Существующая активная собственная сессия MUST иметь приоритет перед новым поручением независимо от чистоты дерева. При работающем агенте CLI MUST наблюдать ту же сессию; когда агент не работает — проверить Git и либо завершить автономную сессию, либо передать её человеку. Остановка CLI MUST NOT сама по себе останавливать или удалять агента Paseo.

#### Scenario: CLI остановлен во время работы агента
- **GIVEN** собственный агент продолжает подготовку коммитов после остановки CLI
- **WHEN** пользователь снова запускает CLI для того же change
- **THEN** CLI находит и сопровождает ту же сессию без повторного рабочего поручения и нового агента

#### Scenario: Коммиты созданы до остановки CLI
- **GIVEN** агент создал коммиты и перестал работать, но CLI остановлен до проверки и закрытия сессии
- **WHEN** CLI возобновляет работу
- **THEN** CLI находит активную сессию, проверяет актуальный Git, закрывает её при чистом дереве и не запускает повторную подготовку

#### Scenario: CLI остановлен после закрытия сессии
- **GIVEN** собственная сессия уже архивирована в Paseo и Git остаётся чистым
- **WHEN** CLI возобновляет работу
- **THEN** CLI завершается по актуальному Git без повторного агента и без восстановления архивированной истории

#### Scenario: После завершённого поручения появилась новая работа
- **GIVEN** предыдущее поручение проверено и окончательно завершено, его коммиты сохранены, а пользователь подготовил новые изменения
- **WHEN** пользователь отдельно запускает подготовку коммитов
- **THEN** CLI различает завершённое поручение и новые изменения и может выдать одно новое поручение в том же workspace

### Requirement: Прямая отправка и граница восстановления

CLI MUST создавать агента одним `create_agent_request`, который одновременно содержит его настройки, встроенное первоначальное поручение и метки происхождения. Перед запросом CLI MUST получить полный актуальный список активных собственных сессий. Неопределённый исход создания MUST завершать текущий запуск с ошибкой и MUST NOT вызывать автоматическое повторение мутации в том же процессе.

При следующем явном запуске CLI MUST сначала искать видимую активную собственную сессию: найденная сессия продолжается, несколько найденных сессий создают препятствие. Если активная сессия не видна, решение снова принимается по актуальному Git: чистое дерево означает отсутствие работы, грязное разрешает одну новую сессию. Предварительное резервирование запроса, ожидание по тайм-ауту как доказательство отсутствия агента и постоянная блокировка по архивированной истории MUST NOT использоваться.

#### Scenario: Потерян ответ на создание агента
- **GIVEN** Paseo мог принять запрос создания, а CLI не получил подтверждение
- **WHEN** текущий процесс обрабатывает неопределённый исход
- **THEN** CLI сообщает ошибку и не повторяет запрос создания автоматически

#### Scenario: Пользователь повторно запускает CLI после прерванного создания
- **GIVEN** предыдущий CLI остановился во время создания, а пользователь проверил состояние Paseo перед повторным запуском
- **WHEN** новая команда читает активные собственные сессии
- **THEN** она продолжает найденную сессию, а при её отсутствии заново решает по актуальной чистоте Git, нужна ли новая попытка

### Requirement: Решения принимаются по актуальным источникам

CLI MUST повторно читать Git, сведения о change и состояние Paseo во время сопровождения и ожидания человека. Перед каждым новым воздействием и подтверждением результата CLI MUST проверять актуальность его оснований. Пропадание change, смена рабочего контекста или ошибка источника MUST приостанавливать воздействия без признания успеха. Ожидание MUST прерываться по сигналу пользователя с сохранением возможности продолжить сессию.

#### Scenario: Источник недоступен во время ожидания
- **GIVEN** CLI ожидает ответа своей сессии
- **WHEN** соединение с Paseo становится недоступным
- **THEN** CLI показывает недоступность, прекращает новые воздействия и после восстановления связи сначала перечитывает состояние
