## Why

Сейчас пользователь сам запускает подготовку коммитов и выясняет после прерывания, закончил ли агент работу. Первое изменение должно передать это сопровождение CLI и проверить основу восстановления будущего Apply workflow на наблюдаемом результате Git.

Основание — согласованная граница первого change в [обсуждении разбиения](../../../docs/discussions/change-boundaries.md#согласованная-граница-управляемая-подготовка-коммитов) и [ограничения продукта](../../../docs/discussions/openspec-apply-orchestrator.md).

## What Changes

- Появится команда подготовки коммитов для явно выбранного активного OpenSpec change: проверка среды, однократное получение неизменяемого снимка конфигурации запуска, восстановление существующего поручения, использование настроек агента только при необходимости новой сессии, запуск нового поручения при наличии незакоммиченных изменений и завершение без агента при отсутствии работы.
- CLI будет находить активный workspace change, различать свои сессии и сессии пользователя и сопровождать не более одного собственного незавершённого поручения выбранного change. Поручения других change не участвуют в этой последовательности: допустимость их параллельной работы и изоляцию Git-контекста определяет пользователь.
- Все операции с Paseo будут выполняться только через совместимый `paseo` CLI и его проверяемый JSON-вывод. Собственный клиент внутреннего протокола Paseo и прямое подключение к daemon не входят в поставку.
- Новая сессия будет создаваться одной фоновой JSON-командой Paseo CLI сразу со встроенным поручением, полным ID активного workspace и метками происхождения. Выполняющийся ход будет ожидаться штатной блокирующей JSON-командой Paseo, после возврата которой состояние подтвердится свежими фильтрами и `inspect`; двухсекундный опрос работающей сессии не используется. Повторный запуск сначала найдёт видимую активную собственную сессию по фильтрам меток и продолжит наблюдать её; закрытые сессии останутся историей и не будут блокировать отдельную новую попытку.
- Успех будет определяться свежей проверкой отсутствия незакоммиченных изменений после завершения работы агента или закрытия сессии. Структурированный отчёт агента и неизменяемый снимок исходного содержимого для этого не требуются; корректность содержательной работы и сохранения изменений в коммитах остаётся ответственностью агента и участвующего пользователя.
- Если агент перестал работать, а Git остаётся изменённым, либо Paseo сообщает ошибку или запрос разрешения, CLI передаст через настроенный канал транспортно-нейтральное уведомление о текущей собственной сессии. Первый адаптер ntfy сформирует безопасный `Title` из типа поручения и change, объяснит причину в тексте без непрозрачного ID сессии и добавит явное действие `Открыть сессию` с Paseo deep-link. Это действие одновременно откроет текущую сессию и очистит уведомление как прочитанное, чтобы прекратить настойчивый звук; отдельный неочищающий переход по всей карточке через `Click` использоваться не будет. Пользователь продолжит работу с тем же агентом и закроет сессию после разрешения ситуации, после чего CLI заново проверит Git.
- Закрытие сессии при грязном Git завершит текущий запуск неуспешно, но не создаст постоянной блокировки: следующий явный запуск сможет выдать новое поручение, если активной собственной сессии уже нет.
- В конфигурации репозитория пользователь будет задавать для новой сессии поддерживаемый встроенный провайдер Paseo, точную модель и необязательный reasoning. Режим разрешений не будет пользовательской настройкой: адаптер совместимой версии обязан выбрать и передать Paseo проверенный режим полного доступа, а неподдерживаемый провайдер, профиль или значение каталога отклонить до мутаций без перехода к настройкам Paseo по умолчанию. Оркестратор отвечает за проверенные параметры своего вызова; установленные пользователем плагины Paseo и их последующие преобразования считаются доверенной пользовательской политикой и не входят в проверку совместимости. Настройки создания и встроенный промпт не будут условием обнаружения, наблюдения или архивирования уже существующей собственной сессии. Рабочие и технические промпты войдут в поставку CLI; прогресс в конфигурации, дополнительных файлах или артефактах OpenSpec храниться не будет.
- **BREAKING**: ещё не завершённая схема настроек уведомлений меняется с верхнеуровневого `ntfy` на дискриминированный вариант `notifications.intervention` с `type`, `url`, необязательным `tokenEnv` и необязательным `priority`. Для ntfy допустимы только канонические `min`, `low`, `default`, `high` и `max`; отсутствие поля означает `default`, а каждый запрос явно передаёт разрешённый приоритет. Секрет указывается только через имя переменной окружения; литеральные токены в JSON не поддерживаются. В границе личного Linux-local workflow конфигурация репозитория, включая полученные из Git и выполненные full-access агентом изменения, считается доверенной пользовательской политикой выбора адреса, переменной токена и приоритета без отдельного подтверждения. `tokenEnv` предназначен для отдельного заменяемого токена уведомлений, а безопасные заголовок, сообщение и deep-link локальной сессии не считаются значимыми конфиденциальными данными. Файл конфигурации читается не более одного раза за запуск: изменения применяет только новый процесс, который сначала восстанавливает видимую активную собственную сессию и не создаёт замену ради смены настроек.
- Действия, проверки, ожидания и препятствия будут по ходу работы видны человеку в русском человекочитаемом stdout; отдельный машиночитаемый формат вывода в эту поставку не входит.

Граница результата — одно поручение подготовки коммитов выбранного change. Обсуждение задачи, Apply, ревью, переход к следующей задаче или фазе и архивирование change относятся к следующим возможностям. Координация и безопасная изоляция параллельной работы разных change остаются ответственностью пользователя.

Граница поставки этого change — Linux, локальный daemon Paseo того же пользователя и локальные рабочий Git-каталог и корень выбранного change. Иная ОС, удалённый daemon и сетевые файловые системы не поддерживаются; CLI сообщает такую среду до создания или изменения workspace и сессий. Пользовательское устройство, открывающее ссылку из первого адаптера ntfy, проверяется отдельно и не обязано входить в эту границу.

## Capabilities

### New Capabilities

- `commit-preparation`: запуск подготовки коммитов, настройки и встроенное поручение, проверяемый результат Git и завершение команды.
- `managed-paseo-sessions`: принадлежность workspace и сессий, последовательность собственных поручений и восстановление без файлового журнала прогресса.
- `intervention-reporting`: передача затруднения человеку, транспортно-нейтральная доставка с первым адаптером ntfy, безопасная ссылка и наблюдаемый ход сопровождения.

### Modified Capabilities

Нет: существующие основные спецификации отсутствуют.

## Impact

Изменение развивает новый Go-модуль и затронет интеграции с Git, OpenSpec CLI, Paseo CLI, транспортно-нейтральный интерфейс уведомлений и его первый HTTP-адаптер ntfy, а также схему конфигурации, тесты и пользовательское руководство. Совместимая версия `paseo` становится внешней зависимостью времени выполнения. Существующая схема OpenSpec и правила коммитов сохраняют роль ограничений для агента; код CLI не будет привязан к графу `intent-driven`.

Долговременные решения будут оформлены в `docs/adr/` со статусом `proposed`. Планирование охватывает всю возможность, а подробные задачи — только первую фазу согласно настроенной схеме.
