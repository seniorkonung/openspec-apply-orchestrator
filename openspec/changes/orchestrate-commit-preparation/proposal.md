## Why

Сейчас пользователь сам запускает подготовку коммитов и выясняет после прерывания, закончил ли агент работу. Первое изменение должно передать это сопровождение CLI и проверить основу восстановления будущего Apply workflow на наблюдаемом результате Git.

Основание — согласованная граница первого change в [обсуждении разбиения](../../../docs/discussions/change-boundaries.md#согласованная-граница-управляемая-подготовка-коммитов) и [ограничения продукта](../../../docs/discussions/openspec-apply-orchestrator.md).

## What Changes

- Появится команда подготовки коммитов для явно выбранного активного OpenSpec change: проверка среды, восстановление существующего поручения, чтение настроек агента только при необходимости новой сессии, запуск нового поручения при наличии незакоммиченных изменений и завершение без агента при отсутствии работы.
- CLI будет находить активный workspace change, различать свои сессии и сессии пользователя и сопровождать не более одного собственного незавершённого поручения выбранного change. Поручения других change не участвуют в этой последовательности: допустимость их параллельной работы и изоляцию Git-контекста определяет пользователь.
- Все операции с Paseo будут выполняться только через совместимый `paseo` CLI и его проверяемый JSON-вывод. Собственный клиент внутреннего протокола Paseo и прямое подключение к daemon не входят в поставку.
- Новая сессия будет создаваться одной фоновой JSON-командой Paseo CLI сразу со встроенным поручением, полным ID активного workspace и метками происхождения. Повторный запуск сначала найдёт видимую активную собственную сессию по фильтрам меток и продолжит наблюдать её; закрытые сессии останутся историей и не будут блокировать отдельную новую попытку.
- Успех будет определяться свежей проверкой отсутствия незакоммиченных изменений после завершения работы агента или закрытия сессии. Структурированный отчёт агента и неизменяемый снимок исходного содержимого для этого не требуются; корректность содержательной работы и сохранения изменений в коммитах остаётся ответственностью агента и участвующего пользователя.
- Если агент перестал работать, а Git остаётся изменённым, либо Paseo сообщает ошибку или запрос разрешения, CLI отправит уведомление ntfy со ссылкой на текущую сессию. Пользователь продолжит работу с тем же агентом и закроет сессию после разрешения ситуации; затем CLI заново проверит Git.
- Закрытие сессии при грязном Git завершит текущий запуск неуспешно, но не создаст постоянной блокировки: следующий явный запуск сможет выдать новое поручение, если активной собственной сессии уже нет.
- В конфигурации репозитория пользователь будет задавать для новой сессии поддерживаемый встроенный провайдер Paseo, точную модель и необязательный reasoning. Режим разрешений не будет пользовательской настройкой: адаптер совместимой версии обязан выбрать проверенный режим полного доступа, а неподдерживаемый провайдер, профиль или значение каталога отклонить до мутаций без перехода к настройкам Paseo по умолчанию. Настройки создания и встроенный промпт не будут условием обнаружения, наблюдения или архивирования уже существующей собственной сессии. Рабочие и технические промпты войдут в поставку CLI; прогресс в конфигурации, дополнительных файлах или артефактах OpenSpec храниться не будет.
- Действия, проверки, ожидания и препятствия будут видны в stdout по ходу работы.

Граница результата — одно поручение подготовки коммитов выбранного change. Обсуждение задачи, Apply, ревью, переход к следующей задаче или фазе и архивирование change относятся к следующим возможностям. Координация и безопасная изоляция параллельной работы разных change остаются ответственностью пользователя.

Граница поставки этого change — Linux, локальный daemon Paseo того же пользователя и локальные рабочий Git-каталог и корень выбранного change. Иная ОС, удалённый daemon и сетевые файловые системы не поддерживаются; CLI сообщает такую среду до создания или изменения workspace и сессий. Пользовательское устройство, открывающее ссылку ntfy, проверяется отдельно и не обязано входить в эту границу.

## Capabilities

### New Capabilities

- `commit-preparation`: запуск подготовки коммитов, настройки и встроенное поручение, проверяемый результат Git и завершение команды.
- `managed-paseo-sessions`: принадлежность workspace и сессий, последовательность собственных поручений и восстановление без файлового журнала прогресса.
- `intervention-reporting`: передача затруднения человеку, уведомления ntfy и наблюдаемый ход сопровождения.

### Modified Capabilities

Нет: существующие основные спецификации отсутствуют.

## Impact

Изменение развивает новый Go-модуль и затронет интеграции с Git, OpenSpec CLI, Paseo CLI и HTTP-интерфейсом ntfy, а также тесты и пользовательское руководство. Совместимая версия `paseo` становится внешней зависимостью времени выполнения. Существующая схема OpenSpec и правила коммитов сохраняют роль ограничений для агента; код CLI не будет привязан к графу `intent-driven`.

Долговременные решения будут оформлены в `docs/adr/` со статусом `proposed`. Планирование охватывает всю возможность, а подробные задачи — только первую фазу согласно настроенной схеме.
