## Phase 1: Видимая собственная сессия продолжается по Paseo

- [x] 1.1 Ввести типизированное состояние собственной сессии в новом Go-модуле
  - **Acceptance criteria:**
    - Создан модуль по design; ключи change, workspace и сессии различаются типами, а внешние данные проходят проверку до создания доверенного наблюдения.
    - Взаимоисключающие варианты представляют отсутствие активной собственной сессии, одну работающую, одну ожидающую действия, закрытие наблюдаемой сессии и неоднозначность; структурированный результат агента и состояние будущего запроса отсутствуют.
    - Проверены некорректные метки, противоречивые состояния и неизвестная версия; используются русские имена и описания тестов.
  - **Verification:** `go test ./internal/orchestrator/...`; `go vet ./internal/orchestrator/...`; Go MCP diagnostics для изменённых файлов. Сверить термины с `CONTEXT.md` и ADR 0001.
  - **Dependencies:** Нет.
  - **Files likely touched:** Новые `go.mod`, `internal/orchestrator/session.go`, `internal/orchestrator/session_test.go`.
  - **Estimated scope:** S.

- [ ] 1.2 Подключаться к локальному Paseo с проверкой протокола и без повторной отправки мутаций
  - **Acceptance criteria:**
    - Реализованы Unix-socket WebSocket-транспорт, handshake, проверка версии, `serverId` и корреляции ответа по установленному контракту Paseo; библиотека с поддержкой собственного dialer выбрана по официальной документации и закреплена в модуле.
    - Обрыв соединения, истечение срока и неподдерживаемый протокол возвращаются как различимые ошибки; чтение можно повторять, отправленные мутации автоматически не повторяются.
    - Сигнал отменяет локальное ожидание, не останавливая и не удаляя агента; размеры сообщений ограничены, секреты и полезная нагрузка не попадают в диагностику.
  - **Verification:** `go test ./internal/paseo/...` с локальным сервером протокола для handshake, потери ответа, неверной корреляции и отмены; Go MCP diagnostics и vulncheck после добавления зависимости.
  - **Dependencies:** 1.1.
  - **Files likely touched:** Новые `internal/paseo/transport.go`, `internal/paseo/transport_test.go`, `internal/paseo/wire.go`; `go.mod`, новый `go.sum`.
  - **Estimated scope:** M.

- [ ] 1.3 Получать полный снимок workspace и активных сессий с проверенной принадлежностью
  - **Acceptance criteria:**
    - Адаптер читает все страницы workspace и агентов, сохраняя полные ID, cwd, метки, workspace, родителя, состояние и `archivedAt`; неполная выборка не превращается в отсутствие сессии.
    - Собственная сессия определяется по design и ADR 0003; ручные сессии, внутренние субагенты, архивированная история и собственные сессии других change не принимаются за активное поручение выбранного change.
    - Несколько подходящих workspace, две активные собственные сессии и повреждённые признаки принадлежности возвращают объясняющую неоднозначность; переименование агента не нарушает корректную связь.
  - **Verification:** `go test ./internal/paseo/... ./internal/orchestrator/...` со снимками нескольких страниц, одинаковых названий, архивированных и ручных сессий, а также поручений разных change; сверить сценарии `managed-paseo-sessions`.
  - **Dependencies:** 1.1, 1.2.
  - **Files likely touched:** Новые `internal/paseo/snapshot.go`, `internal/paseo/snapshot_test.go`, `internal/orchestrator/ownership.go`, `internal/orchestrator/ownership_test.go`; `internal/paseo/wire.go`.
  - **Estimated scope:** M.

- [ ] 1.4 Создавать и архивировать собственную сессию через проверяемые операции Paseo
  - **Acceptance criteria:**
    - Один `create_agent_request` передаёт настройки, встроенный первоначальный промпт и метки `oa.owner`, `oa.version`, `oa.change`, `oa.kind`; ответ проверяется до выдачи ID ядру.
    - Неопределённый исход создания завершает операцию различимой ошибкой и не ставит повтор в очередь; предварительное резервирование, `requestKey` и изменение workspace как состояние поручения отсутствуют.
    - Архивирование проверяется повторным чтением, а потеря его ответа не приводит к слепому повтору или признанию закрытия.
  - **Verification:** `go test ./internal/paseo/...` с фиксацией фактического create payload, потерей ответа и повторным чтением после архивирования; сопоставить поля с `@getpaseo/protocol@0.7.2`.
  - **Dependencies:** 1.2, 1.3.
  - **Files likely touched:** Новые `internal/paseo/agent.go`, `internal/paseo/agent_test.go`; `internal/paseo/wire.go`, `internal/orchestrator/ownership.go`.
  - **Estimated scope:** M.

- [ ] 1.5 Исключать второго локального владельца выбранного change без файлов состояния
  - **Acceptance criteria:**
    - Реализован неблокирующий lock существующего корня выбранного change на Linux; канонически эквивалентные пути к тому же change не обходят ограничение, а разные change не используют общий lock только из-за одного Git common dir.
    - Второй процесс того же change получает объяснение занятости до воздействий на Paseo, а остановка владельца освобождает lock без очистки PID-файлов.
    - Подпроцессные проверки показывают, что обычные и аварийные остановки не оставляют собственных файлов; lock не служит свидетельством состояния сессии Paseo.
  - **Verification:** `go test ./internal/ownership/...` с двумя процессами одного change, канонически эквивалентными путями, разными change в одном Git-репозитории и принудительной остановкой владельца.
  - **Dependencies:** 1.1.
  - **Files likely touched:** Новые `internal/ownership/lock_linux.go`, `internal/ownership/lock_test.go`.
  - **Estimated scope:** S.

- [ ] 1.6 Продолжать одну видимую активную сессию по свежему снимку
  - **Acceptance criteria:**
    - Ядро выбирает относящееся к фазе действие для отсутствующей, работающей, ожидающей действия, архивированной и неоднозначной собственной сессии; каждое воздействие требует свежего полного снимка.
    - Повторное создание ядра с пустой памятью находит ту же видимую активную сессию и не отправляет первоначальное поручение повторно; архивированная сессия не блокирует отдельную будущую попытку.
    - Отмена ожидания оставляет агент в Paseo, а ручная сессия и сессия другого change не наблюдаются и не архивируются этим сопровождением.
  - **Verification:** `go test ./internal/orchestrator/... ./internal/paseo/...` с подменяемыми часами, сменой снимка между чтением и действием и повторным созданием ядра.
  - **Dependencies:** 1.3, 1.4, 1.5.
  - **Files likely touched:** Новые `internal/orchestrator/reconcile.go`, `internal/orchestrator/reconcile_test.go`; `internal/paseo/agent.go`.
  - **Estimated scope:** M.

- [ ] 1.7 Доказать продолжение видимой сессии через реальные границы процесса
  - **Acceptance criteria:**
    - Интеграционный стенд на совместимом daemon использует производственный адаптер, отдельное хранилище и управляемый тестовый провайдер; первоначальный промпт и метки читаются после штатного перезапуска daemon.
    - Проверены остановки после подтверждённого создания, во время работы, при ожидании действия и до или после архивирования: новый процесс находит ту же видимую активную сессию либо корректно видит архивированную историю.
    - Неопределённое создание не повторяется внутри процесса; стенд и документация прямо не заявляют устранение принятого окна между принятием запроса и видимостью сессии. Ручные сессии и поручения другого change остаются вне управления.
  - **Verification:** Создать и выполнить `go test -tags=paseo_integration ./internal/paseo/... ./internal/orchestrator/...` против отдельного daemon; зафиксировать совместимую версию, ID и метки после каждого контролируемого прерывания.
  - **Dependencies:** 1.4, 1.6.
  - **Files likely touched:** Новые `internal/paseo/recovery_integration_test.go`, `internal/orchestrator/recovery_integration_test.go`, `internal/testpaseo/daemon.go`, `internal/testpaseo/provider.go`, `docs/development/paseo-compatibility.md`.
  - **Estimated scope:** M.

- [ ] 1.8 Подтвердить готовность сопровождения видимой сессии к подключению Git
  - **Acceptance criteria:**
    - Условие `Ready to advance` Phase 1 подтверждено результатами 1.7: создание переносит промпт и метки одним запросом, видимая активная сессия продолжается после перезапуска, неоднозначность обнаруживается, ручные сессии не затрагиваются.
    - Пройдены тесты, статические проверки и проверка зависимостей; отсутствуют собственные записи прогресса, резервирование будущего агента и реализация возможностей последующих фаз.
    - Заголовок пакета совпадает с plan, строгая валидация change успешна; перед продолжением требуется отдельное планирование пакета Phase 2.
  - **Verification:** `go test ./...`; `go test -race ./...`; `go vet ./...`; `go test -tags=paseo_integration ./internal/paseo/... ./internal/orchestrator/...`; Go MCP diagnostics и vulncheck; `openspec validate orchestrate-commit-preparation --strict --no-interactive`; проверить отсутствие различий после `gofmt` для новых Go-файлов.
  - **Dependencies:** 1.1, 1.2, 1.3, 1.4, 1.5, 1.6, 1.7.
  - **Files likely touched:** Нет, только проверка и отметка задачи после успешного выполнения.
  - **Estimated scope:** XS.
