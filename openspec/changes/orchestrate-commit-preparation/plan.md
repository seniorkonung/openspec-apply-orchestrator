## Direction

Сначала сделать принадлежность и продолжение уже видимой активной сессии независимыми от памяти процесса. Затем связать это сопровождение с настоящей подготовкой коммитов и простым наблюдаемым критерием — чистым Git после прекращения работы сессии. Последней фазой завершить участие человека в той же сессии, уведомления и сквозную приёмку.

Направление задают [спецификации](specs/managed-paseo-sessions/spec.md), [design](design.md) и [ADR-контекст](adr.md). Все фазы сохраняют различие между собственной активной сессией, ручной сессией пользователя и архивированной историей. Координация параллельной работы разных change остаётся за пользователем.

## Plan Constraints

- Создание передаёт первоначальное поручение и метки одним запросом. Неопределённая мутация не повторяется в том же процессе; узкое окно до видимости сессии принимается только для ручного запуска и не превращается в протокол резервирования.
- Восстановлению подлежит видимая активная собственная сессия. Архивированная сессия не блокирует отдельную новую попытку, а собственный журнал, неизменяемый снимок файлов и структурированный результат агента не вводятся.
- Промежуточные результаты предназначены для последующей реализации внутри change. Поставка всей команды требует достижения последнего результата; завершение промежуточной фазы не означает готовности всей возможности.

## Phase 1: Видимая собственная сессия продолжается по Paseo

**Objective:** Перейти от предположения о пригодности Paseo к проверенному механизму, который создаёт сессию сразу с поручением и метками, однозначно находит её и продолжает после остановки процесса.

**Outcome:** Производственный механизм сопровождения связывает активную сессию с workspace и выбранным change, исключает второй локальный процесс того же change, различает работу, ожидание действия и архивирование и не управляет ручными сессиями. Уже видимая активная сессия находится после повторного запуска без собственного журнала.

**Boundaries:** Включены типы состояния, транспорт Paseo, принадлежность по меткам, прямое создание, наблюдение, архивирование и локальное владение change. Механизм проверяется на ограниченном поручении без изменения рабочего репозитория. Настоящая подготовка коммитов, проверка Git и уведомления относятся к последующим фазам.

**Ready to advance:** На совместимом Paseo подтверждены передача первоначального поручения и меток одним запросом, их сохранность и чтение после перезапуска процесса и daemon, продолжение уже видимой сессии, обнаружение неоднозначности и отсутствие воздействия на ручные сессии. Неопределённое создание не повторяется внутри процесса; испытания не заявляют устранение принятого окна до видимости сессии.

## Phase 2: Подготовка коммитов завершается чистым Git

**Objective:** Превратить проверенное сопровождение в команду одного поручения подготовки всех текущих изменений активного change.

**Outcome:** Команда проверяет среду и настройки, завершается без агента при чистом Git, а при наличии работы создаёт одну сессию с встроенным поручением. Агент самостоятельно анализирует состояние репозитория и создаёт коммиты; после прекращения его работы CLI архивирует сессию и завершается успешно только при чистом Git.

**Boundaries:** Включены рабочая среда и контекст OpenSpec, конфигурация агента, встроенный промпт, чтение чистоты Git и наблюдаемые исходы команды. CLI не доказывает сохранность исходного содержимого и не разбирает структурированный отчёт агента. Полное сопровождение затруднений через уведомления завершается следующей фазой.

**Ready to advance:** Различимы отсутствие работы, работа агента, чистый и грязный Git после завершившегося хода и закрытие сессии. Прерывание после создания коммитов продолжает ту же видимую сессию, чистый Git завершает поручение, а грязный не запускает автоматическую замену в том же вызове. Команда не переходит к другим видам работы.

## Phase 3: Затруднение разрешается в той же сессии с участием человека

**Objective:** Завершить возможность так, чтобы ошибка, запрос разрешения или грязный Git после хода агента не требовали ручного поиска сессии.

**Outcome:** Пользователь получает уведомление с доступным контекстом и ссылкой, продолжает работу с текущим агентом и закрывает сессию после разрешения ситуации. CLI проверяет Git после закрытия: чистое дерево завершает команду, грязное даёт объясняющий неуспех без постоянной блокировки следующей явной попытки.

**Boundaries:** Включены доставка и ограниченные повторы уведомлений, ожидание человека, ручное закрытие, повторная проверка Git, восстановление видимой активной сессии и сквозная приёмка возможности. Обсуждение задач, Apply, ревью и полный workflow остаются за границей change.

**Ready to advance:** Подтверждён весь контракт подготовки коммитов, включая помощь, недоступность интеграций, ручное закрытие при чистом и грязном Git и повторный запуск после закрытой неуспешной попытки. Пользовательский переход из уведомления проверен, а руководство объясняет настройки, границу восстановления и ответственность агента и пользователя за содержательную корректность коммитов.
