## Direction

Сначала сделать принадлежность и продолжение уже видимой активной сессии независимыми от памяти процесса, используя только проверяемые JSON-команды Paseo CLI. Затем связать это сопровождение с настоящей подготовкой коммитов и простым наблюдаемым критерием — чистым Git после прекращения работы сессии. Последней фазой завершить участие человека в той же сессии, уведомления и сквозную приёмку.

Направление задают [спецификации](specs/managed-paseo-sessions/spec.md), [design](design.md) и [ADR-контекст](adr.md). Все фазы сохраняют различие между собственной активной сессией, ручной сессией пользователя и архивированной историей. Координация параллельной работы разных change остаётся за пользователем.

## Plan Constraints

- Создание передаёт первоначальное поручение, полный ID workspace и метки одной командой Paseo CLI. Неопределённая мутация не повторяется в том же процессе; узкое окно до видимости сессии принимается только для ручного запуска и не превращается в протокол резервирования.
- Восстановлению подлежит видимая активная собственная сессия. Архивированная сессия не блокирует отдельную новую попытку, а собственный журнал, неизменяемый снимок файлов и структурированный результат агента не вводятся.
- Paseo доступен только через совместимый CLI и его JSON-контракт; прямой протокол не используется. Граница поставки ограничена Linux, локальным daemon того же пользователя и локальными рабочими каталогами.
- Промежуточные результаты предназначены для последующей реализации внутри change. Поставка всей команды требует достижения последнего результата; завершение промежуточной фазы не означает готовности всей возможности.

## Phase 1: Видимая собственная сессия продолжается по Paseo

**Objective:** Перейти от предположения о пригодности Paseo CLI к проверенному механизму, который одной JSON-командой создаёт сессию с поручением и метками, однозначно находит её в активном workspace и продолжает после остановки процесса.

**Outcome:** Производственный механизм сопровождения через Paseo CLI связывает активную сессию с полным ID активного workspace и выбранным change, исключает второй локальный процесс того же change, различает работу, ожидание действия и архивирование и не управляет ручными сессиями. Уже видимая активная сессия находится после повторного запуска без собственного журнала.

**Boundaries:** Включены типы состояния, адаптер JSON-команд Paseo CLI, активный workspace, принадлежность по меткам change и workspace, прямое создание, наблюдение, архивирование, проверка Linux-local среды и локальное владение change. Прямой протокол и архивированные workspace исключены. Механизм проверяется на ограниченном поручении без изменения рабочего репозитория. Настоящая подготовка коммитов, проверка Git и уведомления относятся к последующим фазам.

**Ready to advance:** На совместимых Paseo CLI и локальном daemon подтверждены передача первоначального поручения, полного ID workspace и меток одной командой, их сохранность и обнаружение через фильтры после перезапуска процесса и daemon, продолжение уже видимой сессии, выявление неоднозначности и отсутствие воздействия на ручные сессии. Неподдерживаемая среда отклоняется до мутаций, неопределённое создание не повторяется внутри процесса, а испытания не заявляют устранение принятого окна до видимости сессии.

## Phase 2: Подготовка коммитов завершается чистым Git

**Objective:** Превратить проверенное сопровождение в команду одного поручения подготовки всех текущих изменений активного change.

**Outcome:** Команда проверяет среду и сначала восстанавливает существующую активную собственную сессию без зависимости от текущих настроек создания. При отсутствии такой сессии она завершается без агента при чистом Git, а при наличии работы проверяет настройки и создаёт одну сессию с встроенным поручением и проверенным системным режимом полного доступа. Пользователь задаёт только поддерживаемые provider, model и reasoning, которые до мутаций сверяются с каталогом совместимой версии Paseo; неподдерживаемые значения не приводят к запуску с default. Агент самостоятельно анализирует состояние репозитория и создаёт коммиты; после завершения его хода CLI архивирует сессию и завершается успешно только при чистом Git. Грязный Git, ошибка агента или неожиданный запрос разрешения приводят к локально видимой передаче человеку и завершению текущего запуска с препятствием, при этом та же сессия остаётся доступной.

**Boundaries:** Включены рабочая среда и контекст OpenSpec, независимое от входов создания восстановление существующей сессии, строгая конфигурация нового агента без пользовательского режима разрешений, немутирующий каталог настроек и версионированный выбор полного доступа, встроенный промпт, чтение чистоты Git, локальное обнаружение потребности в человеке и наблюдаемые исходы команды. CLI не доказывает сохранность исходного содержимого и не разбирает структурированный отчёт агента. Длительное ожидание человека, уведомления, ручное закрытие переданной сессии и повторная проверка Git после него относятся к следующей фазе.

**Ready to advance:** Различимы отсутствие работы, неподдерживаемая настройка до мутаций, работа агента и чистый либо грязный Git после завершившегося хода. Для поддерживаемой конфигурации новая сессия всегда получает проверенный режим полного доступа; пользовательский режим, профиль, неизвестное значение каталога или отсутствие совместимого сопоставления не создают workspace либо сессию и не вызывают fallback. Видимая активная сессия восстанавливается и при отсутствующей, повреждённой или ставшей неподдерживаемой текущей конфигурации; настройки и промпт становятся обязательными только после свежего подтверждения необходимости нового поручения. Прерывание после создания коммитов продолжает ту же видимую сессию, чистый Git завершает поручение, а грязный Git, ошибка агента и неожиданный запрос разрешения локально сообщают потребность в человеке, сохраняют ту же сессию и завершают текущий запуск без автоматической замены. Команда не ждёт ручного закрытия и не переходит к другим видам работы.

## Phase 3: Затруднение разрешается в той же сессии с участием человека

**Objective:** Завершить возможность так, чтобы ошибка, запрос разрешения или грязный Git после хода агента не требовали ручного поиска сессии.

**Outcome:** Пользователь получает уведомление с доступным контекстом и ссылкой, продолжает работу с текущим агентом и закрывает сессию после разрешения ситуации. CLI проверяет Git после закрытия: чистое дерево завершает команду, грязное даёт объясняющий неуспех без постоянной блокировки следующей явной попытки.

**Boundaries:** Включены доставка и ограниченные повторы уведомлений, ожидание человека, ручное закрытие, повторная проверка Git, восстановление видимой активной сессии и сквозная приёмка возможности. Обсуждение задач, Apply, ревью и полный workflow остаются за границей change.

**Ready to advance:** Подтверждён весь контракт подготовки коммитов, включая помощь, недоступность интеграций, ручное закрытие при чистом и грязном Git и повторный запуск после закрытой неуспешной попытки. Пользовательский переход из уведомления проверен, а руководство объясняет настройки, границу восстановления и ответственность агента и пользователя за содержательную корректность коммитов.
