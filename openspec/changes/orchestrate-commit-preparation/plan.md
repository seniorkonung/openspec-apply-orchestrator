## Direction

Сначала сделать принадлежность и продолжение уже видимой активной сессии независимыми от памяти процесса, используя только проверяемые JSON-команды Paseo CLI. Затем связать это сопровождение с настоящей подготовкой коммитов, штатным блокирующим ожиданием выполняющегося хода и простым наблюдаемым критерием — чистым Git после прекращения работы сессии. До признания этой подготовки готовой изолировать единственный активный контракт Paseo за стабильным доменным интерфейсом и заменить его на выбранный точный выпуск без параллельной поддержки старой версии. Последней фазой завершить участие человека в той же сессии, транспортно-нейтральную доставку уведомлений и сквозную приёмку.

Направление задают [спецификации](specs/managed-paseo-sessions/spec.md), [design](design.md) и [ADR-контекст](adr.md). Все фазы сохраняют различие между собственной активной сессией, ручной сессией пользователя и архивированной историей. Координация параллельной работы разных change остаётся за пользователем.

## Plan Constraints

- Создание передаёт первоначальное поручение, полный ID workspace и метки одной командой Paseo CLI. Неопределённая мутация не повторяется в том же процессе; узкое окно до видимости сессии принимается только для ручного запуска и не превращается в протокол резервирования.
- Восстановлению подлежит видимая активная собственная сессия. Архивированная сессия не блокирует отдельную новую попытку, а собственный журнал, неизменяемый снимок файлов и структурированный результат агента не вводятся.
- Paseo доступен только через совместимый CLI и его JSON-контракт; выполняющийся ход ожидается штатной блокирующей возможностью CLI, а последующее решение принимается по свежему полному наблюдению. Прямой протокол не используется. Граница поставки ограничена Linux, локальным daemon того же пользователя и локальными рабочими каталогами.
- В каждый момент поддерживается один точный выпуск Paseo. Его версия, команды, wire JSON, системная семантика и deep-link принадлежат заменяемому внутреннему адаптеру; миграция прекращает поддержку прежнего выпуска и заново подтверждает тот же доменный интерфейс без SemVer-диапазонов и capability probing.
- Ядро сопровождения не зависит от протокола уведомлений. Формат конфигурации версии 1 требует один типизированный канал перед созданием нового production-поручения, первым адаптером остаётся ntfy, а секреты поступают только из окружения. Текущая доступность канала не является условием восстановления уже существующей активной собственной сессии.
- Промежуточные результаты предназначены для последующей реализации внутри change. Поставка всей команды требует достижения последнего результата; завершение промежуточной фазы не означает готовности всей возможности.

## Phase 1: Видимая собственная сессия продолжается по Paseo

**Objective:** Перейти от предположения о пригодности Paseo CLI к проверенному механизму, который одной JSON-командой создаёт сессию с поручением и метками, однозначно находит её в активном workspace и продолжает после остановки процесса.

**Outcome:** Производственный механизм сопровождения через Paseo CLI связывает активную сессию с полным ID активного workspace и выбранным change, исключает второй локальный процесс того же change, различает работу, ожидание действия и архивирование и не управляет ручными сессиями. Уже видимая активная сессия находится после повторного запуска без собственного журнала.

**Boundaries:** Включены типы состояния, адаптер JSON-команд Paseo CLI, активный workspace, принадлежность по меткам change и workspace, прямое создание, наблюдение, архивирование, проверка Linux-local среды и локальное владение change. Прямой протокол и архивированные workspace исключены. Механизм проверяется на ограниченном поручении без изменения рабочего репозитория. Настоящая подготовка коммитов, проверка Git и уведомления относятся к последующим фазам.

**Ready to advance:** На совместимых Paseo CLI и локальном daemon подтверждены передача первоначального поручения, полного ID workspace и меток одной командой, их сохранность и обнаружение через фильтры после перезапуска процесса и daemon, продолжение уже видимой сессии, выявление неоднозначности и отсутствие воздействия на ручные сессии. Неподдерживаемая среда отклоняется до мутаций, неопределённое создание не повторяется внутри процесса, а испытания не заявляют устранение принятого окна до видимости сессии.

## Phase 2: Подготовка коммитов завершается чистым Git

**Objective:** Превратить проверенное сопровождение в команду одного поручения подготовки всех текущих изменений активного change, заменить технический опрос работающего хода штатным ожиданием Paseo и сделать следующий переход Paseo заменой одного активного CLI-контракта за стабильным доменным интерфейсом.

**Outcome:** Команда проверяет среду и сначала восстанавливает существующую активную собственную сессию без зависимости от текущих настроек создания. Работающий ход ожидается штатной блокирующей возможностью Paseo без периодического технического опроса, а после события принадлежность и состояние подтверждаются заново. При отсутствии такой сессии команда завершается без агента при чистом Git, а при наличии работы требует типизированный канал участия человека, проверяет настройки агента и создаёт одну сессию, передавая Paseo встроенное поручение и проверенный системный режим полного доступа. Отсутствующий канал и неподдерживаемые provider, model или reasoning отклоняются до мутаций без запуска с default. Агент самостоятельно анализирует состояние репозитория и создаёт коммиты; после завершения его хода CLI архивирует сессию и завершается успешно только при чистом Git. Грязный Git, ошибка агента или запрос разрешения приводят к локально видимой передаче человеку и завершению текущего запуска с препятствием, при этом та же сессия остаётся доступной. Вся зависимость от точной версии, команд, wire JSON, системной семантики и ссылок Paseo сосредоточена во внутреннем адаптере одного активного контракта; production-команда и ядро сохраняют прежний доменный интерфейс после перехода с 0.7.2 на 0.8.0-beta.1. Установленные пользователем плагины и их преобразования остаются доверенной политикой Paseo за границей проверяемых параметров вызова оркестратора.

**Boundaries:** Включены рабочая среда и контекст OpenSpec, независимое от текущих входов создания восстановление существующей сессии, штатное ожидание работающего хода с последующим свежим наблюдением, обязательный типизированный канал для нового production-поручения, строгая конфигурация нового агента без пользовательского режима разрешений, немутирующий каталог настроек и системный выбор передаваемого режима полного доступа, встроенный промпт, чтение чистоты Git, локальное обнаружение потребности в человеке и наблюдаемые исходы команды. Также включены стабильный доменный модуль Paseo, заменяемый внутренний CLI-адаптер, один точный активный контракт, его миграционное руководство и повторная квалификация существующим стендом. Одновременная поддержка выпусков, SemVer-диапазоны, capability probing, SDK, прямой протокол, инспекция plugin-топологии и доказательство последующих plugin-преобразований исключены. CLI не доказывает сохранность исходного содержимого, не разбирает ответ агента и не принимает сигнал завершения ожидания за результат поручения. HTTP-доставка, длительное ожидание человека, ручное закрытие переданной сессии и повторная проверка Git после него относятся к следующей фазе.

**Ready to advance:** Различимы отсутствие работы, отсутствующий канал или неподдерживаемая настройка до мутаций, работа агента и чистый либо грязный Git после завершившегося хода. Работающая сессия ожидается одной длительной операцией Paseo, её возврат всегда приводит к свежему подтверждению состояния, а прежний короткий цикл технического опроса отсутствует. Для поддерживаемой конфигурации Paseo всегда получает проверенный режим полного доступа и канал участия человека; отсутствующий канал, пользовательский режим, профиль, неизвестное значение каталога или отсутствие совместимого сопоставления не создают workspace либо сессию и не вызывают fallback. Plugin-топология не участвует в проверке совместимости и не изменяет ответственность оркестратора за параметры его собственного вызова. Видимая активная сессия восстанавливается и при отсутствующей, повреждённой или ставшей неподдерживаемой текущей конфигурации; настройки, канал и промпт становятся обязательными для создания только после свежего подтверждения необходимости нового поручения. Прерывание после создания коммитов продолжает ту же видимую сессию, чистый Git завершает поручение, а грязный Git, ошибка агента и запрос разрешения локально сообщают потребность в человеке, сохраняют ту же сессию и завершают текущий запуск без автоматической замены. Команды, wire JSON, версия, системная семантика и ссылка Paseo не встречаются вне активного адаптера, а руководство и контрактные fixtures позволяют следующему агенту заменить его по одному сценарию. Точный контракт 0.8.0-beta.1 заново проходит модульные и сквозные проверки без ветвей поддержки 0.7.2. Команда не ждёт ручного закрытия и не переходит к другим видам работы.

## Phase 3: Затруднение разрешается в той же сессии с участием человека

**Objective:** Завершить возможность так, чтобы ошибка, запрос разрешения или грязный Git после хода агента не требовали ручного поиска сессии и не связывали ядро сопровождения с конкретным протоколом уведомлений.

**Outcome:** Пользователь получает через один настроенный канал уведомление с доступным контекстом и ссылкой, продолжает работу с текущим агентом и закрывает сессию после разрешения ситуации. Ядро передаёт типизированное событие через общий интерфейс, а первый адаптер ntfy получает секрет только из окружения. Если канал исчез после создания поручения, CLI локально показывает ошибку доставки и ссылку, не прекращая сопровождение существующей сессии и не считая это штатным режимом только через stdout. CLI с ограниченной частотой наблюдает idle-сессию, возвращается к штатному ожиданию при новом ходе и проверяет Git после закрытия: чистое дерево завершает команду, грязное даёт объясняющий неуспех без постоянной блокировки следующей явной попытки.

**Boundaries:** Включены типизированная конфигурация одного канала, транспортно-нейтральный интерфейс, адаптер ntfy, безопасное получение необязательного токена из окружения, доставка и ограниченные повторы уведомлений, ожидание человека, ручное закрытие, повторная проверка Git, восстановление видимой активной сессии и сквозная приёмка возможности. Загружаемые плагины, несколько одновременных каналов, произвольные webhook-шаблоны, обсуждение задач, Apply, ревью и полный workflow остаются за границей change.

**Ready to advance:** Подтверждён весь контракт подготовки коммитов, включая отказ без канала до создания нового поручения, восстановление существующей сессии без текущего канала, помощь, недоступность интеграций, ручное закрытие при чистом и грязном Git и повторный запуск после закрытой неуспешной попытки. Проверены безопасная конфигурация поддерживаемого адаптера, авторизованная и неавторизованная доставка, отсутствие сетевого запроса при недоступном секрете и сохранение сопровождения при отсутствующем канале либо ошибке доставки. Пользовательский переход из уведомления проверен, а руководство объясняет настройки, границу восстановления и ответственность агента и пользователя за содержательную корректность коммитов.
